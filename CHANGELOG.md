## [Unreleased]

### Added

- A rounding rule per customer: in the form of a customer (*New customer* and *Edit customer*) the new select **Rounding** (German: *Rundung*) offers **Use the global setting** (the default, so nothing changes for existing customers), **No rounding**, or a step (5 minutes, 10 minutes, quarter hour, half hour, hour) rounded **up** or **to the nearest**. The customer's rule wins over the global setting in its reports (screen, PDF, CSV), on the Dashboard and in the month summary: a customer can be rounded to a half hour while another one is billed exactly. A customer with its own rule shows it under its name. When the customers of the month do not share one rule, the notes on the Dashboard say *Rounding differs by customer.* and each customer's report names its own rule. Existing installs: back up, then apply the migration with `kubectl -n time-tracking exec -i deploy/postgres -- sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backend/migrations/009_customer_rounding.sql`, rebuild the images and restart the backend and the frontend.
- More rounding steps: **Round time entries** (German: *Zeiteinträge runden*) in the settings now also offers **5 minutes**, **10 minutes** and **Hour (60 minutes)** next to quarter and half hour. Reports print hours with two decimals, and a step of 5 or 10 minutes is not a whole hundredth of an hour: 5 minutes prints as 0,08 h and 10 minutes as 0,17 h, so twelve entries of 5 minutes add up to 0,96 h and six of 10 minutes to 1,02 h (quarter hours, half hours and full hours are exact). The report sentence names the new steps too (*Hours rounded up to full hours.*, *Hours rounded to the nearest 10 minutes.*). Existing installs: back up, then apply the migration (after `007_settings_rounding.sql`, which it needs) with `kubectl -n time-tracking exec -i deploy/postgres -- sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backend/migrations/008_settings_rounding_steps.sql`, rebuild the images and restart the backend and the frontend.
- Rounding of tracked time in reports: in **Settings**, group **Time and billing**, **Round time entries** (German: *Zeiteinträge runden*) rounds the hours of each entry to a **quarter hour** or a **half hour**, with **Direction** (*Richtung*) **Up** (the default) or **To the nearest**. Each entry is rounded on its own; an entry never counts less than one step; stored entries are never changed. The Reports page, the PDF and the CSV show the rounded hours, the amounts are calculated from them (hours × rate equals the amount on every row), and, if you switch on **Name the rounding rule in reports** (*Rundungsregel in Berichten nennen*, off by default), the Reports page and the PDF say which rule was applied (*Hours rounded up to quarter hours.*). The CSV has the rounded hours without a note and keeps the exact start and end times. The setting also applies to reports of past months; files you have already downloaded do not change. The default is **No rounding**, so nothing changes until you choose a step. The Dashboard's billing figures (the billable amount, *By customer* and *Billing*) and the month summary on the Time tracking page use the rounded hours too, so they equal the report; each of those cards names the rule. The tracked time stays exact: the timer, the entry lists, the Entries search, and on the Dashboard *This week*, *This month*, the chart and the recent entries. Existing installs: back up, then apply the migration with `kubectl -n time-tracking exec -i deploy/postgres -- sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backend/migrations/007_settings_rounding.sql`, rebuild the images and restart the backend and the frontend.
- The first setting, in the group **Time and billing** (German: *Zeit und Abrechnung*): **Show hourly rate and amounts in reports** (German: *Stundensatz und Beträge in Berichten anzeigen*). It is off by default, so reports look as before. The Reports page starts from it in every browser; its checkbox *Show hourly rate and amounts* still changes only the report you are looking at, with its PDF and CSV downloads, for that visit. If the settings cannot be loaded, the Reports page shows an error with *Try again* and starts without amounts.
- The Settings page can hold options in named groups and saves all of them with one **Save** button (German: *Speichern*): it confirms *Settings saved.*, and when saving fails it shows an error and keeps what you typed. The settings load once when the tool opens, so a saved change applies on every page without a reload.
- New **Settings** page (German: *Einstellungen*) at the end of the main navigation, at `/settings`, for options that apply to the whole tool in every browser. Existing installs: back up, then apply the two migrations with `for f in 005_settings 006_settings_show_amounts; do kubectl -n time-tracking exec -i deploy/postgres -- sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backend/migrations/$f.sql; done`, rebuild the images and restart the backend and the frontend.
- Monthly reports can include the hourly rate and the amount per project and the total amount, in the PDF (an amount column, a block *Per project* and a *TOTAL AMOUNT* line), in the CSV (two columns, *Rate (EUR/h)* and *Amount (EUR)*) and in the report data. They are off unless asked for: without the option every report looks exactly as before. Amounts are in euros; each entry's hours are rounded to hundredths and its amount to cents, so the printed numbers add up exactly. On the Reports page, the checkbox *Show hourly rate and amounts* turns them on.
- Every page has its own address (`/`, `/time-tracking`, `/entries`, `/reports`): a reload keeps the page, the browser's back and forward buttons move between pages, and you can bookmark a page or open it in a new tab (also with a middle click on the navigation). A link opened while logged out leads to the login and then to that page. An unknown address shows a *Page not found* page with a link to the Dashboard. The browser tab's title names the page, and focus moves to the new page's heading for keyboard and screen reader users.
- The selected customer, project and month are part of the address too (`/time-tracking/3/7`, `/reports/3/2026-09`): a reload, a bookmark or a link you send keeps them, and Back returns to the customer you had open before. The places that open another page with a selection (Dashboard, *Open report*, *Open* on the Entries page) are real links now, so "open in a new tab" works. An address for a customer or project that does not exist (any more) says so and links back. On the Reports page, the month arrows wait until a customer is chosen.
- New **Entries** page (German: *Einträge*) between *Time tracking* and *Reports*: search the descriptions of all customers and filter by customer, project and period (today, this week, last month, a custom range and more), sorted newest or oldest first, with the number of entries and hours found. It opens with the current month; *Reset filters* clears every filter. The filters can be collapsed and the active ones stay visible as chips you can remove. A result opens the customer's page in *Time tracking*.
- Reports can be downloaded as a CSV file for spreadsheets: **Download CSV** (German: *CSV herunterladen*) on the Reports page next to *Download PDF* lists the same entries of the customer and month with date, start, end, customer, project, description and hours. German files use `;` between the columns and decimal commas, English files use `,` and decimal points, so the file opens correctly in Excel in the matching language. With the amounts option (see above) the file also has the hourly rate and the amount of each entry.
- Login: the tool asks for an email and a password and has a *Log out* button in the header. There is one user; create it (and change the password later) with `node src/scripts/set-user.js you@example.com`, which asks for the password: at least 10 characters with a capital letter, a number and a special character. You stay logged in for up to 30 days, or until you have not used the tool for 14 days. After 10 failed logins the login is blocked for up to 15 minutes. Existing installs: see "Upgrading an Existing Install to the Login" in `k8s/README.md`.
- The tool is served over HTTPS at https://time-tracking.local; http redirects to it. `k8s/setup-tls.sh` creates a certificate your browsers trust (needs `mkcert`). Existing installs run it once and restart the backend, see "Upgrading an Existing Install to HTTPS" in `k8s/README.md`.
- Tooling: every backend and frontend test run ends with a timing report: time per test file, the 10 slowest tests (`TEST_TIMINGS=all` for every test) and the time of the entire run.

### Changed

- Tooling: the documentation chapters for the Dashboard, Time tracking and Reports now show a screenshot of the page (`documentation/ui/images/`); the browser review chapter explains how to take them, and a test checks that every linked image exists and has an alt text.
- Tooling: the router tests wait for the address, the page title and the focus instead of checking them at once, so they no longer fail at random.
- The Reports page no longer shows hourly rates and amounts by default; tick *Show hourly rate and amounts* to see them again, also in the PDF and CSV downloads. The choice the browser used to remember is gone: the default is now a setting (see above), and the old stored choice is removed from your browser on the next visit of the Reports page.
- The backend and the database can no longer be reached directly from other devices or other pods; Docker Compose publishes only the web page, and only on this machine (development ports: see the README). Anyone who can open the tool can still use it, and the login protects the data. Existing installs: see "Network Policy" in `k8s/README.md`.
- Only the tool's own backend can connect to the database in the cluster; backups are not affected. Existing installs: see "Network Policy" in `k8s/README.md`.
- Tooling: the frontend test run prints its timing report again after the Vitest 5 update.
- Tooling: changes reach `main` through pull requests; `main` is protected and needs the passing checks `backend tests` and `frontend tests`.
- Tooling: CodeQL code scanning is on for the repository.
- Tooling: `CLAUDE.md` is reordered into Things worth knowing, Commands, Layout, Styling, Kubernetes, Testing and Rules, and the rules are merged into groups with the pull request process as a numbered list.
- Tooling: new documentation chapter "Browser review": how to review a change in the browser with a throwaway database and sample data, also for branches in a git worktree. A test checks that every documentation chapter is linked from the index.
- Screen readers now read each project's and customer's share of the month's hours (e.g. "70 % of total") next to the hours in the month summary and in "By customer" on the Dashboard.
- Tooling: the repository has a Code of Conduct (Contributor Covenant 2.1).
- Tooling: fixed a test of `k8s/setup-tls.sh` that failed at random; its fake `openssl` now reads its input like the real one.
- The API answers `401` without a login for everything except `/health`. Anything else that calls it, such as scripts, has to log in first (`POST /api/auth/login`) and send the cookie.
- Tooling: Dependabot no longer proposes major updates of the Babel plugin that Jest needs in version 7.
- Tooling: test and config packages updated (Jest 30, jest-dom 7, js-yaml 5, dotenv 18).
- Tooling: dependencies updated to their latest major versions (React 19, Vite 8, Vitest 5, Tailwind CSS 4, Lingui 6, Express 5, jsdom 30).
- PDF report downloads: file names with accents or other non-ASCII letters now show a plain `?` in the basic file name; the full name stays in the extended `filename*` that browsers use. A plain ASCII file name is sent without quotes.
- Tooling: GitHub test workflow, issue and pull request templates, `CONTRIBUTING.md` and `SECURITY.md`.
- Tooling: Dependabot checks the dependencies and GitHub Actions weekly.
- The README warns that the API has no login.
- Tooling: the `test-engineer` agent reports test timings: the time of the test files it adds, their slowest tests and, for a full run, the entire-run time.
- Tooling: the frontend tests moved from next to the code into `frontend/tests/`, mirroring `src/`.
- Tooling: the project rules now ask for a changelog entry per change, a test run before every push, cleaning up test data in the real database, a marker for tests that document known bugs, and closing implemented GitHub issues.

### Fixed

- On the Time tracking page, the month summary no longer prints a large billable amount over the number of entries: the three figures take the space they need and wrap onto a new line on narrow screens.
- Stopping the timer can no longer save an entry that ends before it starts (for example when the browser's clock is behind): the server's time is used instead. Entries that already end before they start can be corrected by editing them (the edit form now opens them with the end on the day of the start).
- Creating a project for a customer that does not exist now answers `400` ("Customer not found") instead of a server error `500`. The same goes for a customer id that is not a number.
- With a remote database, the backend now starts: it waits for the database in `DATABASE_URL` instead of always for the in-cluster Postgres.
- The arrows of the dropdowns (project, customer and status selects, forms) now have space to the right border, in the light and the dark theme.
